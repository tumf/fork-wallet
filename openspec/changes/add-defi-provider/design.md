## Request concurrency and trace
Each approval request has crypto.randomUUID requestId, epoch, origin/account/chain and endpoint binding plus immutable payload. Exactly one outstanding approval (including dispatching) at a time, parallel reads allowed. states admitted/held/dispatching/submitted/rejected/response-lost/unknown/failed/cancelled. Record admission before any dispatch; release allowed once and only matching held ID. Scope changes/revoke/disconnect increment epoch, invalidate not-yet-dispatched requests, and reject stale continuation even if async policy/ownership check later returns. Use synchronous compare and state transition immediately before rpc invocation; never await between final comparison and transition. Already dispatched writes remain attributed to their original chain, never “cancelled”. No snapshot/reset API in this stage. No write retries or same-calldata dedupe. lost = RPC hash already recorded but withheld from browser; timeout/invalid reply after dispatch is unknown even if effect not confirmed. Read actual tx by hash to bind sender/nonce when available; failure to enrich cannot turn submitted hash into no-send. Exactly-once is not claimed. Don't write raw signatures or full typed payload into logs. calls remains source-compatible where possible but fields/outcome are explicitly versioned in types and migration.
