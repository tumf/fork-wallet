# Design

## Minimal implementation
- Extend `test/pack-consumer.js` with a `--runtime` option while preserving the existing optional tarball-output argument and no-argument behavior. Add a package script `test:pack:runtime` invoking it. Unknown --options or more than one positional output path fail exit 2; --runtime plus one output path is allowed. Duplicate --runtime is invalid.
- Reuse `test/integration.test.js` and `examples/local-anvil/harness.js`. A test-only absolute `FORK_WALLET_CONSUMER_DIR` selects `require.resolve('fork-wallet', {paths:[consumer]})` and `require.resolve('fork-wallet/anvil', {paths:[consumer]})`. Verify resolved paths are physically inside that consumer's installed package and never fall back. Unset mode retains existing relative imports. Do not modify src or declarations.
- No string-rewritten copy of the integration suite and no second suite of transaction assertions. Reuse dApp assets and the server fixture from the repo, but inject the installed requireOwnedPort into startStaticServer through an optional option; use the existing source default only when that option is absent in source mode. Avoid even eagerly importing repository anvil code in installed mode. The integration test passes the resolved installed function; existing SDK/legacy harness callers retain their default. Resolve both consumer and package paths with realpath (including macOS /var aliases). Hashes alone do not prove selection: retain resolved index/anvil paths, requireOwnedPort supplier path, consumer directory and tgz digest; the parent verifies all suppliers are physically under its exact consumer/node_modules/fork-wallet directory. Hash installed files as supporting information.
- Spawn the existing bounded `test/run-gate.js test/integration.test.js` with the selected consumer environment, existing Playwright/Anvil prerequisites, only PATH, HOME, TMPDIR, PLAYWRIGHT_BROWSERS_PATH and the explicitly constructed test variables; exclude NODE_PATH/NODE_OPTIONS and other inherited values. Use the repository's installed Playwright test dependency; it is not a packaged runtime dependency. No dependency installation from the network is needed for runtime beyond the existing offline local-tgz installation.
- Preserve evidence under ignored `artifacts/pack-runtime/<unique-run>/` before deleting the consumer, on success or failure. Prevent collisions between invocations. The parent sets FORK_WALLET_EVIDENCE_DIR to this exact fresh directory, the test uses it as OUT only in consumer mode, and parent requires evidence.json there. Require result===PASS, childrenStopped===true, cleanupError/stopError absent and the installed realpaths matching the parent-created consumer, AND actual child exit 0. Preserve evidence even on failed child and fail when missing. Consumer deletion failure is also nonzero. Return nonzero for prerequisite, spawn, timeout, failed child, missing evidence, bad installed selection or cleanup failure. A printed PASS is not a substitute for child exit 0 and validated evidence.
- Existing integration cleanup remains authoritative for owned Anvil/browser/server. Fix any discovered cleanup reporting omission within that test only if necessary for this gate; never kill foreign processes. Preserve pack temporary-directory cleanup in finally. No retry of writes.

## Failure and negative checks
Use lightweight node assertions for option parsing and no-fallback installed resolution: invalid/missing directory or a resolved package outside the directory fails before starting Anvil. A failing runtime child must remain failure even when basic CJS/ESM checks pass. Keep these assertions local to the touched test scripts rather than introducing a framework or production abstraction.

## Boundaries
Allowed: test/pack-consumer.js, test/integration.test.js, examples/local-anvil/harness.js, package.json script only, README.md, ACCEPTANCE.md and this spec delta. A tiny focused test file under test is allowed if needed for negative cases. package-lock only if package-manager metadata requires it, no dependency/version changes. No source, distribution allowlist, legacy/signing policy, network timeout or third-party sample changes.
