# Signing design (normative)

## Public API
Keep 0.2.0 APIs; add optional InstallOptions.signing = { validateSignature(request): void|Promise<void> }. Reject missing/non-function callback and unknown signing option fields at install. signing absent means both methods explicitly 4200; no policy implied by validateTransaction. signing enabled only when every configured chain ID is 31337 or 31338. Mandatory beforeSend remains a trusted owner guard, not a proof of fresh key. Generic users are responsible for using only disposable keys; provided helper starts --mnemonic-random and accepts no supplied key.

SignatureRequest is a deep-frozen discriminated union: {method:'personal_sign', account, message:hex} or {method:'eth_signTypedData_v4', account, typedData:{types,primaryType,domain,message}}. Request has no mutable references to params. Run policy before admission and after async ownership preflight, with final synchronous epoch comparison and dispatch transition; reject callback errors as fixed sanitized policy refusal (no thrown content). Already-admitted/held requests share the same single outstanding approval slot as sends/permissions. Node-only controls never become page-callable. Per-chain account switching uses existing registration semantics.

## Input contract
personal_sign takes exactly [even-length 0x bytes,address]; message maximum 65536 bytes, empty structurally allowed but actual Anvil rejection preserved/sanitized. Do not require an unmeasured empty-message positive assertion; no substitution of nonempty bytes. SDK-generated ethers/viem payloads must be measured through actual fixture, never assume direct-RPC feasibility proves them. No plain UTF-8 string/address-first alias. Address must equal active authorized account (case-insensitive); no other unlocked or impersonated address. Forward normalized [message,activeAccount].
eth_signTypedData_v4 takes exactly [address, JSON string OR plain object]. String/object serialized input <=65536 UTF-8 bytes, JSON-safe own plain objects/arrays only; no undefined/nonfinite/bigint/functions/prototype pollution keys (__proto__,prototype,constructor), max depth32 and total nodes4096. All parsed JSON number values must satisfy Number.isSafeInteger; reject floats and unsafe integers -32602. Large int/uint values must be decimal/hex strings, never rounded JS numbers. Numeric lexical exponent spelling is not a separate restriction: after parse only the safe integer value matters. Parse JSON text exactly once with JSON.parse, then validate and send only that parsed object serialized anew. Policy and upstream must use the identical parsed value; duplicate keys therefore follow JSON.parse last-key behavior with no separate raw parser. Top-level keys exactly types,primaryType,domain,message. types plain object max64 entries, each array max64 unique field entries exactly {name,type} nonempty strings <=128 chars, require EIP712Domain and primaryType definition; primaryType not EIP712Domain. domain exactly from {name,version,chainId,verifyingContract,salt}, chainId mandatory equal active chain; accept decimal digit string, canonical hex quantity or safe integer, convert for comparison using BigInt, never unsafe Number. name/version strings if present; verifyingContract exactly20bytes; salt32bytes. EIP712Domain field definitions must correspond to domain keys/types; no undeclared/mismatched domain fields. message plain object. Anvil remains authoritative for EIP712 type syntax/value encoding; do not implement hashing/encoding/recovery in runtime. Policy inspects validated but otherwise value-preserving data. Invalid nested types/values that pass local structural bounds must fail at Anvil (sanitized code), never dummy success. Object and JSON text inputs normalize to same plain parsed typedData, forward [activeAccount,JSON.stringify(typedData)] to Anvil. SDK acceptance proves normalization does not change recovered digest for that fixture.

## Approval and outcomes
Add two methods to approval/method types and Node nextRequest. Exported METHODS/APPROVAL_METHODS are static supported-capability lists including both methods, NOT a statement of enabled policy. Per-instance dispatch enforces opt-in. Disabled nextRequest({method:sign,...}) fails -32602. Handle order: frame guard, request shape, signing opt-in check (absent4200 recordedUnsupported reason signing-disabled), params array, transport4900, authorization4100, input validation-32602, lost-mode check, policy. Extend UnsupportedRecord reason union with signing-disabled. Global mode lost approves only connection/permission/switch as before, but explicit signing lost is NOT supported: when setMode('lost') active, sign fails -32602 before policy/admission without consuming one-shot override; bypass existing non-send lost-to-approve downgrade; nextRequest({method:sign,mode:'lost'}) fails -32602. release(id,'lost') on held sign fails without releasing it; same id remains available for approve/reject. Document this intentional limit. Successful signing outcome signed, not submitted; wallet.submitted remains transaction hashes ONLY. signature-generated RPC success but transport failure -> unknown; no retry. If scope changes after dispatch and a well-formed signature arrives, keep attribution original epoch/account/chain, record signed-discarded, signatureReturned=true, delivered=false and discard signature; return lastScopeChange mapped disconnect4900, chain4901, revoke/account4100. Use existing lastScopeChange precedence, cannot undo generation. Before returning any signature synchronously recheck epoch, connected, authorization, active chain/account. RPC result must match /^0x[0-9a-f]{130}$/i; invalid result is unknown, fixed -32603, delivered=false. Valid live success records signed, signatureReturned=true, delivered=true. Add signed-discarded state and both booleans to types/migration. Ordinary call records contain requestId/method/account/chain/epoch/mode/times/outcome, inputHash sha256 of normalized request and domain chainId/verifyingContract summary, signatureReturned boolean (well-formed signature received from Anvil), delivered boolean (returned to caller); NEVER message/typedData/signature. Errors on signing paths use fixed messages and numeric upstream code only, strip error.data/transport body/policy throw contents that might echo secrets. Preserve existing transaction/read revert data behavior.

## Validation/proof
Signing browser suite uses its own policy-enabled BrowserContext, while existing sdk-compat default-disabled signing4200 assertions remain unchanged. Add test/signing-compat.test.js to existing bounded test:sdk runner (whole four-file gate bound180s unchanged, mandatory prerequisites no skips; record total elapsed in ACCEPTANCE and fail on timeout, never weaken bound just to obtain PASS); browser bundle uses existing exact dev pins, no remote imports. Fresh isolated BrowserContext with serviceWorkers:block, existing route/CSP deny outside local app and owned gateway, WebSocket blocked. No trace/HAR/video on signing contexts. Do not screenshot or JSON.stringify page return values containing signature. Fixture message is a non-auth text and typed data is local-only TestNote (not Permit/Permit2/SIWE), domain chain31337/31338 and local fixture verifyingContract. Use random helper accounts, never known key or impersonation.
For each ethers/viem/wagmi-core real browser path, exercise personal and typed signing through their exported actions, then within memory verify both ethers verifyMessage/verifyTypedData and viem recoverMessageAddress/recoverTypedDataAddress equal active account. Keep browser signature in memory only; return booleans and safe metadata to Node. Use safe assertions on booleans, never equal(signature,...) which prints values. Include typed JSON string and object direct provider requests in browser, array/bytes/nested struct fixture to catch digest mutation. Actual RPC calls, no dummy signature mocks in acceptance. Unit fake RPC success may use synthetic hex ONLY for local state-machine tests labelled stub, never cryptographic acceptance.
Negative tests: disabled default still4200; connect not blanket signature permission; wrong account/domain, invalid input, untrusted frame/origin, read gateway batch sign, rejection, policy throwing an embedded sentinel, upstream echo error, timeout after dispatch, concurrent sign/send, hold wrong-id/double-release, revoke/account-change/chain-switch while policy awaits or held, chain-switch after dispatch no stale delivery. Count signing RPC dispatches to prove reject/cancel zero; generated signatures are never logged even on failures. Node in-memory stub counters prove race interleavings; real browser signs against Anvil and verifies account switches/chain domain behavior. Redaction tests inject sentinel and check calls/errors/evidence serialization excludes sentinel. Harden test assertion failures accordingly.
